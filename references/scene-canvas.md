# Scene: 无限画布 / 信息图 / 知识地图

> 空间叙事，而非线性滚动。适合呈现复杂逻辑关系、流程对比、品牌全景。

---

## 定位

- 用于：知识体系展示、流程对比、品牌系统全景、多维度信息呈现
- 受众：需要快速理解全局关系的人
- 目标：让人在 30 秒内看到全局，然后自由探索细节

---

## 核心原则

### 1. 逻辑先行，位置即语义

画布不是随意摆放节点——**每个节点的空间位置必须传达逻辑关系**。

```
时间先后 → 从左到右
因果推导 → 从上到下
并列对比 → 水平对齐
包含关系 → 嵌套或缩进
分叉路径 → 对称分列
```

**禁止**：为了"好看"而打乱逻辑顺序。位置错了，逻辑就乱了。

### 2. 分区明确，一眼可读

每个区域有清晰的视觉边界和标签。区域之间留白≥100px。

```
┌─────────────────────────────────────┐
│  区域标签                            │
│  ┌─────┐  ┌─────┐  ┌─────┐        │
│  │节点1│  │节点2│  │节点3│        │
│  └─────┘  └─────┘  └─────┘        │
│                                     │
│  ← 120px 留白 →                     │
│                                     │
│  区域标签                            │
│  ┌──────────┐  ┌──────────┐       │
│  │  节点4   │  │  节点5   │       │
│  └──────────┘  └──────────┘       │
└─────────────────────────────────────┘
```

### 3. 节点类型丰富但不杂乱

每个区域使用**不同的节点类型**，但同一区域内节点样式一致：

| 用途 | 节点类型 | 特征 |
|------|---------|------|
| 核心主题 | Hero 大卡 | 品牌色满底，最大尺寸 |
| 流程步骤 | 步骤卡片 | 顶部色条 + 大编号 |
| 关键洞察 | 引用卡片 | 浅底色 + 左侧色条 |
| 警告/陷阱 | 警示卡片 | 暖黄底 + 红色强调 |
| 对比/分支 | 分支卡片 | 并排双色顶条 |
| 成果展示 | 成果面板 | 暗底 + 网格排列 |
| 补充说明 | 标签条 | 小尺寸，灰底 |

### 4. 连线克制，只连必要的

- **同一区域内的流程节点**：水平实线连接（→）
- **区域之间的因果关系**：垂直虚线连接（⇢）
- **不连所有节点**——只有逻辑相邻的才连
- 连线颜色使用品牌色 15-25% 透明度

### 5. 留白是叙事语言

画布不是塞满的。每个区域最少保留 15-20% 空白。拥挤=业余。

## 区域结构

一个典型的品牌系统画布：

```
┌──────────────────────────────────────────────┐
│  Zone 1: 核心主题 (居中偏上)                   │
│  Hero大卡：这个画布在说什么                    │
│                                              │
│  Zone 2: 核心原则 (主题上方或侧方)              │
│  引用卡片：一句话概括的核心洞察                 │
│                                              │
│  Zone 3: 流程/步骤 (主题下方，横排)             │
│  步骤卡片 × N，左→右排列                      │
│                                              │
│  Zone 4: 关键洞察/陷阱 (流程下方)               │
│  警示卡片 × 2-3，并列展示                     │
│                                              │
│  Zone 5: 分支/对比 (并列分列)                  │
│  分支卡片 × 2，左右对称                       │
│                                              │
│  Zone 6: 最终产出 (最底部)                     │
│  成果面板：交付了什么                          │
└──────────────────────────────────────────────┘
```

**注意**：不是必须 6 个区域。3-6 个区域根据内容灵活增减。

## 交互规范

### 缩放

- 初始缩放：以 Hero 节点居中，占视口约 40% 面积
- 缩放范围：0.2x ~ 2.0x
- 缩放方式：滚轮（以光标为中心）+ 底部工具栏 ± 按钮
- 缩放步进：每次 10%

### 平移

- 空白区域拖拽平移
- 不拦截节点上的点击事件
- 平移时不触发节点 hover 效果

### 动画

- 禁止 bounce / elastic
- 缩放过渡使用 ease-out，350ms
- 节点 hover：translateY(-2px) + 阴影加深，150ms

### 工具栏

- 位置：底部居中
- 样式：暗底半透明，圆角，与品牌暗面板一致（#3D342F）
- 内容：− 缩小 / 百分比 / + 放大 / 复位
- 可编辑版额外提供：+节点 / 连接 / 重置

### 可编辑画布（V1）

> 不做复杂白板工具，只解决“能连接、能移动、能改内容、能保存”。

#### 数据驱动

画布必须由数据结构驱动，而不是把所有节点和连线写死成静态 DOM。最小结构：

```js
{
  zones: [['CORE IDEA', 2380, 520]],
  nodes: [['hero', 'hero', 2300, 620, '标题', '说明', '标签']],
  edges: [['hero', 'step-1', 'dashed', '开始']]
}
```

字段含义：
- `zones`：区域标签、x、y
- `nodes`：id、类型、x、y、标题、正文、辅助信息
- `edges`：起点 id、终点 id、线型、可选标签

#### 自动连线

- 使用 SVG 层绘制连接线
- 连线根据节点当前位置自动计算，不手写固定坐标
- 节点移动后必须实时重绘连线
- 线型只保留 3 种：`solid`、`dashed`、`soft`
- 连线仍然克制，只连接真正相邻的逻辑

#### 节点拖拽

- 空白区域拖拽 = 平移画布
- 节点右上角 / 节点主体拖拽 = 移动节点
- 缩放状态下拖拽距离必须按 scale 校正
- 拖拽结束后保存节点坐标
- 节点拖拽时不触发画布平移

#### 内容编辑

- 节点标题、正文、编号/标签可直接编辑
- 使用 `contenteditable`，粘贴时只保留纯文本
- 编辑后自动保存到 localStorage
- 不做复杂侧边栏，避免过度工具化

#### 保存与重置

- 使用 localStorage 保存当前画布数据
- 页面刷新后恢复上次编辑状态
- 工具栏提供“重置”按钮，恢复模板默认数据
- `Ctrl/Cmd + S` 可手动保存

#### 创建与编辑连接

- 第一版只做简单连接模式：点击“连接”，再依次点击两个节点
- 不做复杂锚点、拖线、多端口连接
- 新连接默认使用 `dashed`，后续需要时再扩展
- 连接线可点击选中
- 选中连接后：`Delete/Backspace` 删除，`1/2/3` 切换实线/虚线/弱线，`L` 修改标签

#### 删除与复制

- 节点卡片右上角提供删除按钮 `×`
- 删除节点时必须同步删除所有相关连接
- `Ctrl/Cmd + D` 复制当前选中节点，复制节点默认偏移 40px
- 保持轻量，不做复杂右键菜单或属性面板

## 尺寸规范

| 元素 | 尺寸 |
|------|------|
| 画布总尺寸 | 由内容决定（通常 4000-6000px 宽 × 3000-5000px 高） |
| Hero 主卡 | 360-420px 宽 |
| 步骤卡片 | 220-260px 宽 |
| 警示卡片 | 260-300px 宽 |
| 分支卡片 | 240-280px 宽 |
| 成果面板 | 340-400px 宽 |
| 区域间距 | 200-300px（垂直）/ 120-200px（水平） |
| 同区域节点间距 | 80-120px |
| 区域标签字号 | 13px, Arial Unicode, 大写, #8A8178 |

## 节点样式细则

### 连线

```css
.conn-line {
  stroke: rgba(188, 69, 40, 0.2);
  stroke-width: 1.5;
  stroke-dasharray: 6 4;
}
```

- 实线：同一区域内的线性流程
- 虚线：跨区域的因果关系
- 颜色：只用品牌色透明度，不用其他颜色

### 区域标签

```css
.zone-label {
  font-family: 'Arial Unicode MS', 'Arial Unicode', sans-serif;
  font-size: 13px;
  font-weight: 600;
  color: #8A8178;
  letter-spacing: 0.08em;
  text-transform: uppercase;
}
```

## 禁忌

- ❌ 无逻辑地任意摆放节点（位置必须传达语义）
- ❌ 所有节点用同一种样式（失去层次感）
- ❌ 连线过多（只连逻辑相邻的）
- ❌ 区域之间没有足够的留白
- ❌ 缩放动画过于花哨
- ❌ 使用非品牌色做连线或装饰
- ❌ 信息密度过高（一个区域塞 6+ 个节点）
- ❌ 没有区域标签（让人不知道在看什么）
- ❌ 可编辑画布做成复杂白板工具（第一版不做多人协作、复杂锚点、侧边属性面板）
- ❌ 节点可移动但连线不跟随更新
- ❌ 内容可编辑但刷新后丢失
